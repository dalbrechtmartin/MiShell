\hypertarget{md_rapports_2README__EN_autotoc_md3}{}\doxysection{\texorpdfstring{Overview}{Overview}}\label{md_rapports_2README__EN_autotoc_md3}
Mi\+Shell is a mini-\/shell implemented in C, developed as part of a school project. This project allowed me to explore the basic mechanisms of a command interpreter\+: parsing, execution, child process management, and logical operators.\hypertarget{md_rapports_2README__EN_autotoc_md4}{}\doxysection{\texorpdfstring{Important\+: Feature Clarification}{Important\+: Feature Clarification}}\label{md_rapports_2README__EN_autotoc_md4}
Redirections ({\ttfamily \texorpdfstring{$<$}{<}}, {\ttfamily \texorpdfstring{$>$}{>}}, {\ttfamily \texorpdfstring{$>$}{>}\texorpdfstring{$>$}{>}}), logical operators ({\ttfamily \&\&}, {\ttfamily \texorpdfstring{$\vert$}{|}\texorpdfstring{$\vert$}{|}}), and pipes ({\ttfamily \texorpdfstring{$\vert$}{|}}) {\bfseries{were mandatory}} according to the project specification (FM02). However, from my understanding, the specification did {\bfseries{not}} explicitly require implementing them as {\bfseries{built-\/ins}} (features coded directly into the shell).

This meant I had a choice\+:


\begin{DoxyEnumerate}
\item {\bfseries{Implement them myself}} (redirections via {\ttfamily dup2()}, parsing operators, etc.) – which I did initially but abandoned because it was too complex
\item {\bfseries{Delegate them to the system shell}} via {\ttfamily sh -\/c} – which is what I did subsequently for pipes and {\ttfamily \texorpdfstring{$\vert$}{|}\texorpdfstring{$\vert$}{|}}
\end{DoxyEnumerate}

The only commands that {\bfseries{had to be built-\/in}} were\+: {\ttfamily cd}, {\ttfamily pwd}, {\ttfamily echo}, {\ttfamily exit} (FM03).

⬆ Back to top\hypertarget{md_rapports_2README__EN_autotoc_md5}{}\doxysection{\texorpdfstring{Development Approach}{Development Approach}}\label{md_rapports_2README__EN_autotoc_md5}
\hypertarget{md_rapports_2README__EN_autotoc_md6}{}\doxysubsection{\texorpdfstring{Phase 1\+: Simple Commands Without Arguments}{Phase 1\+: Simple Commands Without Arguments}}\label{md_rapports_2README__EN_autotoc_md6}
At first, I started with the essentials\+: {\bfseries{executing simple commands}}. The goal was to be able to enter a command (e.\+g., {\ttfamily pwd}, {\ttfamily ls}) and display it correctly.


\begin{DoxyItemize}
\item Creation of built-\/in commands\+: {\ttfamily cd}, {\ttfamily pwd}, {\ttfamily echo}, {\ttfamily exit}
\item Basic structure without functions initially
\item A simple loop that reads input and executes
\end{DoxyItemize}\hypertarget{md_rapports_2README__EN_autotoc_md7}{}\doxysubsection{\texorpdfstring{Phase 2\+: Execution of External Commands}{Phase 2\+: Execution of External Commands}}\label{md_rapports_2README__EN_autotoc_md7}
Next, to execute {\bfseries{any command}}, not just my built-\/ins, I added the ability to launch external commands via {\ttfamily execvp()} by creating a child process ({\ttfamily fork()}).

{\bfseries{Key decision}}\+: If a command was not a built-\/in, instead of raising an error, I {\bfseries{delegate its execution to the child process}} which will search for it in the system {\ttfamily PATH}. This proved {\bfseries{very useful later}} because this approach allowed me to easily handle complex operators.\hypertarget{md_rapports_2README__EN_autotoc_md8}{}\doxysubsection{\texorpdfstring{Phase 3\+: Arguments and Redirections}{Phase 3\+: Arguments and Redirections}}\label{md_rapports_2README__EN_autotoc_md8}
I then added {\bfseries{argument handling}} ({\ttfamily ls -\/al}) and {\bfseries{redirections}} ({\ttfamily \texorpdfstring{$>$}{>}}, {\ttfamily \texorpdfstring{$>$}{>}\texorpdfstring{$>$}{>}}, {\ttfamily \texorpdfstring{$<$}{<}}) – two mandatory features of the specification. Parsing became more complex\+:


\begin{DoxyItemize}
\item Tokenize the command line
\item Detect redirections
\item Apply redirections in the child process with {\ttfamily dup2()}
\end{DoxyItemize}

⬆ Back to top\hypertarget{md_rapports_2README__EN_autotoc_md9}{}\doxysubsection{\texorpdfstring{Phase 4\+: Operators – My Biggest Challenge}{Phase 4\+: Operators – My Biggest Challenge}}\label{md_rapports_2README__EN_autotoc_md9}
The specification required supporting the {\ttfamily \&\&} (logical AND), {\ttfamily \texorpdfstring{$\vert$}{|}\texorpdfstring{$\vert$}{|}} (logical OR) operators and {\bfseries{pipes}} ({\ttfamily \texorpdfstring{$\vert$}{|}}). This is where I {\bfseries{really struggled}} because initially I mistakenly thought I had to manage them entirely as "{}built-\/ins"{}.

{\bfseries{My initial attempts}} were too complex\+:


\begin{DoxyItemize}
\item Attempt 1\+: Parse all operators at the same time → very nested and hard to follow code
\item Attempt 2\+: Store commands in complex structures → too many cases to handle
\end{DoxyItemize}

{\bfseries{The final solution}}\+: I opted for a {\bfseries{minimalist approach}}\+:


\begin{DoxyEnumerate}
\item {\bfseries{Split only on {\ttfamily \&\&}}} → this gives me at most 3 commands (in accordance with {\ttfamily \doxylink{typedef_8h_ad14effda14501a769b3d46984d43aa00}{MAX\+\_\+\+CMDS}})
\item {\bfseries{Keep pipes AND {\ttfamily \texorpdfstring{$\vert$}{|}\texorpdfstring{$\vert$}{|}} inside commands}} → rather than parsing them myself, I pass them to the system shell
\item {\bfseries{Create a {\ttfamily parse\+\_\+single\+\_\+command()} function}} that handles {\bfseries{one command}} at a time
\end{DoxyEnumerate}

Thus\+:


\begin{DoxyItemize}
\item {\ttfamily ps \&\& ls} → two commands executed sequentially (handled by Mi\+Shell)
\item {\ttfamily ls \texorpdfstring{$\vert$}{|} grep "{}.txt"{}} → {\bfseries{a single command}} passed to {\ttfamily sh -\/c} which handles the pipe
\item {\ttfamily false \texorpdfstring{$\vert$}{|}\texorpdfstring{$\vert$}{|} echo "{}ok"{}} → {\bfseries{a single command}} passed to {\ttfamily sh -\/c} which handles the {\ttfamily \texorpdfstring{$\vert$}{|}\texorpdfstring{$\vert$}{|}}
\item {\ttfamily ps \&\& ls \texorpdfstring{$\vert$}{|} grep "{}.txt"{}} → two commands\+: {\ttfamily ps} on one side, {\ttfamily ls \texorpdfstring{$\vert$}{|} grep "{}.txt"{}} on the other
\end{DoxyItemize}

{\bfseries{Advantage}}\+: The code becomes {\bfseries{very readable}}. Pipes and {\ttfamily \texorpdfstring{$\vert$}{|}\texorpdfstring{$\vert$}{|}} are not my concern – I let the shell handle them via {\ttfamily sh -\/c}. I just need to manage the logical split on {\ttfamily \&\&}.

⬆ Back to top\hypertarget{md_rapports_2README__EN_autotoc_md10}{}\doxysubsection{\texorpdfstring{Phase 5\+: Redirections with Builtins}{Phase 5\+: Redirections with Builtins}}\label{md_rapports_2README__EN_autotoc_md10}
One final challenge\+: builtins ({\ttfamily echo}, {\ttfamily pwd}) did not support redirections. I added a check\+: if a builtin has a redirection, it is executed via the child process (like an external command).

⬆ Back to top\hypertarget{md_rapports_2README__EN_autotoc_md11}{}\doxysubsection{\texorpdfstring{Phase 6\+: Command History – Well-\/\+Thought-\/\+Out Persistence}{Phase 6\+: Command History – Well-\/\+Thought-\/\+Out Persistence}}\label{md_rapports_2README__EN_autotoc_md11}
At first, I had a simple idea\+: save each command in a {\ttfamily mishell\+\_\+history.\+txt} file. But quickly, I ran into a common problem with relative paths.

{\bfseries{The problem}}\+:

When I used a relative path ({\ttfamily mishell\+\_\+history.\+txt}), the file was created in the current directory at shell startup. But as soon as a user did {\ttfamily cd}, the current directory changed! The next saved command created a {\bfseries{new file}} in the new directory instead of continuing to write in the original one.

{\bfseries{My attempts}}\+:


\begin{DoxyEnumerate}
\item {\bfseries{First idea}}\+: Use the {\ttfamily \$HOME} variable to store history in the user\textquotesingle{}s home directory. But on Windows/\+WSL, this variable is not always defined, and it wasn\textquotesingle{}t really what I wanted.
\item {\bfseries{Second idea}}\+: Keep a relative path but add a global {\ttfamily history\+\_\+path} variable and pass it everywhere. It worked, but it was redundant and inelegant.
\end{DoxyEnumerate}

{\bfseries{The final solution}}\+:

I implemented a {\bfseries{static global variable {\ttfamily initial\+\_\+cwd}}} that saves the current directory at shell startup via {\ttfamily getcwd()}. Then, no matter where we navigate with {\ttfamily cd}, the history is always written to the same place\+: {\ttfamily \texorpdfstring{$<$}{<}startup\+\_\+directory\texorpdfstring{$>$}{>}/mishell\+\_\+history.txt}.

{\bfseries{Implementation}}\+:

In {\ttfamily \doxylink{mishell_8c_a3c04138a5bfe5d72780bb7e82a18e627}{main()}}, we first check if the {\ttfamily -\/c} argument is present. If the argument is not provided, we switch to normal interactive mode. I simply reused the existing parsing and execution functions.\hypertarget{md_rapports_2README__EN_autotoc_md14}{}\doxysubsection{\texorpdfstring{Note on Environment Variables (FM06)}{Note on Environment Variables (FM06)}}\label{md_rapports_2README__EN_autotoc_md14}
Environment variables are managed via the built-\/in {\ttfamily export} command. This command uses {\ttfamily putenv()} to modify the environment of the current process and all child processes created afterwards.

{\bfseries{Implementation}}\+:

The {\ttfamily \doxylink{functions_8h_a02a85854505e4af389e6bcef12c2884b}{export\+\_\+cmd()}} function\+:


\begin{DoxyEnumerate}
\item Verifies that the argument contains an {\ttfamily =}
\item Duplicates the string (because {\ttfamily putenv()} does not copy it)
\item Calls {\ttfamily putenv()} to modify the environment
\item Variables remain available to all child processes launched afterwards
\end{DoxyEnumerate}\hypertarget{md_rapports_2README__EN_autotoc_md15}{}\doxysubsection{\texorpdfstring{Note on Aliases (FM07)}{Note on Aliases (FM07)}}\label{md_rapports_2README__EN_autotoc_md15}
For {\bfseries{system shell aliases}} (like {\ttfamily ll} for {\ttfamily ls -\/al}), no special implementation is needed in Mi\+Shell. Since an alias is not a recognized built-\/in command, it is automatically treated as an {\bfseries{external command}} and executed via {\ttfamily fork() + execvp()}. The system shell handles resolving the alias. This works naturally without additional code.\hypertarget{md_rapports_2README__EN_autotoc_md16}{}\doxysubsection{\texorpdfstring{Responsibility Distribution}{Responsibility Distribution}}\label{md_rapports_2README__EN_autotoc_md16}

\begin{DoxyItemize}
\item {\bfseries{Execution modes}}\+:
\begin{DoxyItemize}
\item Interactive mode (prompt {\ttfamily Mi\+Shell\texorpdfstring{$>$}{>} \$})

\end{DoxyItemize}

\item {\ttfamily \&} (background)
\end{DoxyItemize}
\item {\bfseries{Pipes}}\+: {\ttfamily \texorpdfstring{$\vert$}{|}} (delegated to the system shell via {\ttfamily sh -\/c})
\item {\bfseries{Redirections}}\+: {\ttfamily \texorpdfstring{$<$}{<}} (input), {\ttfamily \texorpdfstring{$>$}{>}} (output), {\ttfamily \texorpdfstring{$>$}{>}\texorpdfstring{$>$}{>}} (append)
\item {\bfseries{History}}\+: All commands are automatically logged in {\ttfamily mishell\+\_\+history.\+txt}
\end{DoxyItemize}
